Abstract

Executive Overview

The Smart Campus Lost & Found System is an algorithmic campus utility platform engineered specifically for educational campuses such as Dr. D. Y. Patil Technical Campus (DYPTC), Talegaon-Varale, Pune. Everyday life on a bustling technical campus involves frequent misplacement of personal belongings—including laptops, wireless earbuds, scientific calculators, campus smart cards, hostel keys, and college bags. Conventional paper-based security registers result in delayed retrievals, lack of real-time cross-referencing, and potential vulnerabilities to unauthorized fraudulent claims.

To resolve these challenges while demonstrating core academic computing principles, this project implements a full-stack, high-performance web architecture written strictly in ISO C++17. All business logic, record lifecycle management, and search/sort operations run natively in compiled C++ code powered by the Crow multi-threaded microframework and SQLite3 database. The front-end is crafted with pure semantic HTML5 and responsive CSS3, deliberately avoiding client-side JavaScript to maintain zero dependency overhead and 100% deterministic server-side rendering.

Algorithmic & Data Structures Integration

This coursework model actively integrates fundamental and advanced Data Structures and Algorithms (DSA) studied in the Semester 03 Computer Engineering curriculum:

  • Structured Records: An encapsulated Item struct groups item identifiers, timestamps, locations, contact info, and custody status.
  • Dynamic Array Caching: A std::vector<Item> maintains in-memory data for $O(1)$ random access and cache-friendly contiguous layout.
  • Master Sorting Engine: Implements Merge Sort ($O(N \log N)$ stable), Insertion Sort ($O(N)$ adaptive on nearly-sorted data), and Bubble Sort ($O(N^2)$ with early-exit optimization).
  • Dual Searching Comparator: Implements Linear Search ($O(N)$ multi-criteria filtering) alongside Binary Search ($O(\log N)$ divide-and-conquer) on pre-sorted arrays.
  • Ranked Priority Queue (Max-Heap): Implements std::priority_queue with a custom functor to rank potential auto-matches by a 6-factor multi-attribute similarity score.
  • Fuzzy String Matching: Employs Dynamic Programming Levenshtein Distance ($O(M imes N)$) to tolerate student spelling errors, fused with Jaccard Token Similarity to handle word permutation shifts.
Zero-Knowledge Blind Custody (Anti-Fraud Security):
To prevent malicious users from browsing found items and filing fabricated loss claims, the platform implements a Central Custody protocol. Regular students only lodge lost reports and inspect personal match status through private, cryptographic Claim Tokens (/track). The complete catalog and sorting benchmarks remain strictly guarded for authorized Admin evaluation (/admin), resolving real-world security while enabling full academic evaluation.

Problem Statement & Objectives

1. Background

In educational institutions, campus infrastructure spans multiple multi-storey academic buildings, specialized workshops, central libraries, cafeteria areas, sports grounds, and student hostels. Hundreds of items are misplaced weekly. In current manual workflows, students must physically walk to multiple security booths (Gate 1, Library Desk, Hostel Warden Office) to inquire about lost articles. Manual inquiry is error-prone, prone to privacy leakage of phone numbers, and lacks proactive automated matching.

2. Problem Statement

"To design, develop, and benchmark a secure, thread-safe, algorithmic Lost and Found web management system using C++17, demonstrating the practical application of sorting algorithms (Merge Sort, Bubble Sort, Insertion Sort), searching techniques (Linear vs Binary Search), Dynamic Programming string distance (Levenshtein), and Max-Heap Priority Queues to automate belongings recovery on the DYPTC campus."

3. Objectives

  1. Algorithmic Demonstration: Implement and benchmark Merge Sort, Bubble Sort, and Insertion Sort with real-time microsecond ($\mu s$) timing and swap counters.
  2. Divide-and-Conquer Search: Contrast Linear Search ($O(N)$) with Binary Search ($O(\log N)$) on pre-sorted datasets.
  3. Automated Matching Engine: Build a 6-Factor Multi-Attribute scoring engine ranking potential matches into a Max-Heap Priority Queue.
  4. Fuzzy Typo Tolerance: Apply Levenshtein Distance DP ($O(M imes N)$) and Jaccard Token overlap to match misspelled item names.
  5. Anti-Fraud Security: Enforce Zero-Knowledge Blind Custody so unauthorized students cannot browse found inventories to fabricate false ownership claims.
  6. Zero-JavaScript Architecture: Deliver a fast, responsive, modern web UI purely through C++ server-side templating and CSS3.
  7. Persistent Storage: Guarantee durability across server restarts using SQLite3 with parameterized prepared statements.

Data Structures Used & Justification

1. Encapsulated Record Structure (struct Item)

Each lost or found entity is modeled as an encapsulated C++ structure grouping id, type (LOST/FOUND), name, category, colour, location, date, description, contact_name, student_id, claim_token, and status. Justification: Prevents disjointed parallel arrays and guarantees atomic object manipulation during sorting and database mapping.

2. Dynamic Contiguous Array (std::vector<Item>)

The campus inventory is loaded into a std::vector<Item>. Justification: The number of misplaced items varies dynamically. Unlike raw C-style arrays (Item arr[100]), vectors resize dynamically and provide contiguous memory cache locality, optimizing CPU instruction cache performance during iterative searches and sorting.

3. Priority Queue / Max-Heap (std::priority_queue)

Employed in dsa::findRankedMatches() with custom comparator MatchComparator. Justification: Pairing $N$ lost items with $M$ found items produces $N imes M$ pairs. Sorting all pairs using QuickSort or Merge Sort costs $O(K \log K)$ where $K = N imes M$. A Max-Heap dynamically holds the highest similarity score at the root in $O(1)$ and extracts top-ranked candidates in $O(K \log 5)$ time, radically conserving CPU and memory resources.

4. Sorting Suite (Merge, Insertion, and Bubble Sort)

  • Merge Sort ($O(N \log N)$ Stable): Chosen as the default production sorter. Divide-and-conquer guarantees $O(N \log N)$ performance even in worst-case scenarios, and stability ensures that chronological registration order is preserved for items with identical dates.
  • Insertion Sort ($O(N)$ Best / $O(N^2)$ Worst): Ideal for incremental additions. When 1-2 new lost items arrive into an already sorted list, Insertion Sort shifts elements in $O(N)$ time with zero extra space ($O(1)$).
  • Bubble Sort ($O(N^2)$ Worst): Incorporated for educational benchmarking in the DSA Lab. Enhanced with an early-exit swapped boolean flag to terminate immediately when input is already ordered ($O(N)$).

5. Searching Suite (Linear vs Binary Search)

  • Linear Search ($O(N)$): Necessary for unsorted, multi-attribute filtering across category, color, location, and keywords simultaneously.
  • Binary Search ($O(\log N)$): Applied after Merge Sorting by item name. Halves search intervals on each iteration, achieving lookup in 10 operations for 1,024 records.

6. Hash Table Inverted Index (std::unordered_map)

Maps categories to lists of record IDs (e.g., "Electronics" → [1, 4, 9]) for instantaneous $O(1)$ average subset lookups, and powers the bilingual English-to-Marathi translation engine.

// 1. Dynamic Programming Levenshtein Distance (O(M * N))
inline int levenshteinDistance(const std::string& s1, const std::string& s2) {
    const size_t m = s1.size(), n = s2.size();
    if (m == 0) return static_cast<int>(n);
    if (n == 0) return static_cast<int>(m);

    std::vector<std::vector<int>> dp(m + 1, std::vector<int>(n + 1, 0));
    for (size_t i = 0; i <= m; ++i) dp[i][0] = static_cast<int>(i);
    for (size_t j = 0; j <= n; ++j) dp[0][j] = static_cast<int>(j);

    for (size_t i = 1; i <= m; ++i) {
        for (size_t j = 1; j <= n; ++j) {
            int cost = (std::tolower(s1[i - 1]) == std::tolower(s2[j - 1])) ? 0 : 1;
            dp[i][j] = std::min({ dp[i - 1][j] + 1,        // Deletion
                                  dp[i][j - 1] + 1,        // Insertion
                                  dp[i - 1][j - 1] + cost  // Substitution
                                });
        }
    }
    return dp[m][n];
}

// 2. Jaccard Token Similarity (Set Theory: |A ∩ B| / |A ∪ B|)
inline double jaccardSimilarity(const std::string& s1, const std::string& s2) {
    auto tokensA = tokenize(s1);
    auto tokensB = tokenize(s2);
    if (tokensA.empty() && tokensB.empty()) return 1.0;
    if (tokensA.empty() || tokensB.empty()) return 0.0;

    std::unordered_set<std::string> setA(tokensA.begin(), tokensA.end());
    std::unordered_set<std::string> setB(tokensB.begin(), tokensB.end());

    int intersect = 0;
    for (const auto& t : setA) {
        if (setB.find(t) != setB.end()) intersect++;
    }
    int unionCount = static_cast<int>(setA.size() + setB.size()) - intersect;
    return (unionCount <= 0) ? 0.0 : (static_cast<double>(intersect) / unionCount);
}

// 3. Bubble Sort with Early Exit Optimization (O(N^2) / O(N) Best)
inline void bubbleSort(std::vector<Item>& items, const std::string& sortBy, bool asc, SortMetrics& m) {
    auto start = std::chrono::high_resolution_clock::now();
    m.algorithm_name = "Bubble Sort";
    m.comparisons = 0; m.swaps_or_shifts = 0;
    const size_t n = items.size();

    for (size_t i = 0; i < n; ++i) {
        bool swapped = false;
        for (size_t j = 0; j + 1 < n - i; ++j) {
            if (compareItems(items[j + 1], items[j], sortBy, asc, m.comparisons)) {
                std::swap(items[j], items[j + 1]);
                m.swaps_or_shifts++;
                swapped = true;
            }
        }
        if (!swapped) break; // Optimized Early Termination
    }
    auto end = std::chrono::high_resolution_clock::now();
    m.duration_microseconds = std::chrono::duration_cast<std::chrono::microseconds>(end - start).count();
}

// 4. Stable Divide-and-Conquer Merge Sort (O(N log N) Guaranteed)
inline void merge(std::vector<Item>& items, int left, int mid, int right, 
                  const std::string& sortBy, bool asc, SortMetrics& m) {
    int n1 = mid - left + 1;
    int n2 = right - mid;
    std::vector<Item> L(items.begin() + left, items.begin() + mid + 1);
    std::vector<Item> R(items.begin() + mid + 1, items.begin() + right + 1);

    int i = 0, j = 0, k = left;
    while (i < n1 && j < n2) {
        if (compareItems(L[i], R[j], sortBy, asc, m.comparisons)) {
            items[k++] = L[i++];
        } else {
            items[k++] = R[j++];
        }
        m.swaps_or_shifts++;
    }
    while (i < n1) items[k++] = L[i++];
    while (j < n2) items[k++] = R[j++];
}

inline void mergeSortInternal(std::vector<Item>& items, int left, int right, 
                              const std::string& sortBy, bool asc, SortMetrics& m) {
    if (left < right) {
        int mid = left + (right - left) / 2;
        mergeSortInternal(items, left, mid, sortBy, asc, m);
        mergeSortInternal(items, mid + 1, right, sortBy, asc, m);
        merge(items, left, mid, right, sortBy, asc, m);
    }
}

// 5. Binary Search (O(log N)) on Name Field
inline std::vector<Item> binarySearchByName(std::vector<Item> items, const std::string& q, SearchMetrics& m) {
    SortMetrics sm;
    mergeSort(items, "name", true, sm); // Prerequisite: Ensure Pre-sorted Data

    int low = 0, high = static_cast<int>(items.size()) - 1;
    std::string target = toLower(q);
    std::vector<Item> results;

    while (low <= high) {
        m.comparisons++;
        int mid = low + (high - low) / 2;
        std::string midName = toLower(items[mid].name);

        if (midName.find(target) != std::string::npos) {
            results.push_back(items[mid]);
            break;
        } else if (midName < target) {
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }
    return results;
}

// 6. Priority Queue Max-Heap Auto-Matches Ranking Engine
inline std::vector<MatchResult> findRankedMatches(const std::vector<Item>& lostItems, 
                                                  const std::vector<Item>& foundItems) {
    std::priority_queue<MatchResult, std::vector<MatchResult>, MatchComparator> maxHeap;

    for (const auto& lost : lostItems) {
        for (const auto& found : foundItems) {
            MatchResult res = evaluateMatch(lost, found);
            if (res.overall_score >= 30.0) { // Candidate threshold
                maxHeap.push(res);
            }
        }
    }

    std::vector<MatchResult> ranked;
    while (!maxHeap.empty()) {
        ranked.push_back(maxHeap.top()); // Highest score at root
        maxHeap.pop();
    }
    return ranked;
}
} // namespace dsa

  • Merge Sort offers predictable, stable $O(N \log N)$ sorting for institutional inventories regardless of dataset disorder.
  • Binary Search delivers logarithmic $O(\log N)$ item retrieval when paired with pre-sorted structures.
  • Max-Heap Priority Queues provide an optimal approach to ranking candidate matches without executing costly full $O(K \log K)$ sorting over Cartesian pair products.
  • Dynamic Programming (Levenshtein) and Jaccard Set Overlap successfully compensate for human spelling inconsistencies and keyword order variations.
  • Zero-Knowledge Blind Custody (RBAC) ensures rigorous protection against fraudulent claims, while retaining complete administrative transparency for academic viva evaluation.
