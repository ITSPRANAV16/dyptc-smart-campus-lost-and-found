Abstract

Executive Overview

The Smart Campus Lost & Found System is an algorithmic campus utility platform engineered specifically for educational campuses such as Dr. D. Y. Patil Technical Campus (DYPTC), Talegaon-Varale, Pune. Everyday life on a bustling technical campus involves frequent misplacement of personal belongings—including laptops, wireless earbuds, scientific calculators, campus smart cards, hostel keys, and college bags. Conventional paper-based security registers result in delayed retrievals, lack of real-time cross-referencing, and potential vulnerabilities to unauthorized fraudulent claims.

To resolve these challenges while demonstrating core academic computing principles, this project implements a full-stack, high-performance web architecture written strictly in ISO C++17. All business logic, record lifecycle management, and search/sort operations run natively in compiled C++ code powered by the Crow multi-threaded microframework and SQLite3 database. The front-end is crafted with pure semantic HTML5 and responsive CSS3, deliberately avoiding client-side JavaScript to maintain zero dependency overhead and 100% deterministic server-side rendering.

Algorithmic & Data Structures Integration

This coursework model actively integrates fundamental and advanced Data Structures and Algorithms (DSA) studied in the Semester 03 Electronics & Computer Engineering curriculum:

  • Structured Records: An encapsulated CampusItem record groups item identifiers, timestamps, locations, contact info, and custody status.
  • Dynamic Array Caching: A std::vector<CampusItem> maintains in-memory data for O(1) random access and cache-friendly contiguous layout.
  • Master Sorting Engine: Implements Merge Sort (O(N log N) stable), Insertion Sort (O(N) adaptive on nearly-sorted data), and Bubble Sort (O(N²) with early-exit optimization).
  • Dual Searching Comparator: Implements Linear Search (O(N) multi-criteria filtering) alongside Binary Search (O(log N) divide-and-conquer) on pre-sorted arrays.
  • Ranked Priority Queue (Max-Heap): Implements std::priority_queue with a custom functor to rank potential auto-matches by a 6-factor multi-attribute similarity score.
  • Fuzzy String Matching: Employs Dynamic Programming Levenshtein Distance (O(M × N)) to tolerate student spelling errors, fused with Jaccard Token Similarity to handle word permutation shifts.
Zero-Knowledge Blind Custody (Anti-Fraud Security):
To prevent malicious users from browsing found items and filing fabricated loss claims, the platform implements a Central Custody protocol. Regular students only lodge lost reports and inspect personal match status through private, cryptographic Claim Tokens (/track). The complete catalog and sorting benchmarks remain strictly guarded for authorized Admin evaluation (/admin), resolving real-world security while enabling full academic evaluation.

Problem Statement & Objectives

1. Background

In educational institutions, campus infrastructure spans multiple multi-storey academic buildings, specialized workshops, central libraries, cafeteria areas, sports grounds, and student hostels. Hundreds of items are misplaced weekly. In current manual workflows, students must physically walk to multiple security booths (Gate 1, Library Desk, Hostel Warden Office) to inquire about lost articles. Manual inquiry is error-prone, prone to privacy leakage of phone numbers, and lacks proactive automated matching.

2. Problem Statement

"To design, develop, and benchmark a secure, thread-safe, algorithmic Lost and Found web management system using C++17, demonstrating the practical application of sorting algorithms (Merge Sort, Bubble Sort, Insertion Sort), searching techniques (Linear vs Binary Search), Dynamic Programming string distance (Levenshtein), and Max-Heap Priority Queues to automate belongings recovery on the DYPTC campus."

3. Objectives

  1. Algorithmic Demonstration: Implement and benchmark Merge Sort, Bubble Sort, and Insertion Sort with real-time microsecond timing and swap counters.
  2. Divide-and-Conquer Search: Contrast Linear Search (O(N)) with Binary Search (O(log N)) on pre-sorted datasets.
  3. Automated Matching Engine: Build a 6-Factor Multi-Attribute scoring engine ranking potential matches into a Max-Heap Priority Queue.
  4. Fuzzy Typo Tolerance: Apply Levenshtein Distance DP (O(M × N)) and Jaccard Token overlap to match misspelled item names.
  5. Anti-Fraud Security: Enforce Zero-Knowledge Blind Custody so unauthorized students cannot browse found inventories to fabricate false ownership claims.
  6. Zero-JavaScript Architecture: Deliver a fast, responsive, modern web UI purely through C++ server-side templating and CSS3.
  7. Persistent Storage: Guarantee durability across server restarts using SQLite3 with parameterized prepared statements.

4. Scope & Limitations

Scope: Covers all academic zones of DYPTC (Central Library, Canteen, AI&DS Labs, Architecture Studio, Parking, Hostels). Provides administrative oversight, CSV audit exports for NAAC documentation, and automated ownership matching.

Limitations: Final physical handover requires physical in-person verification with institutional Student ID at Gate 1 Central Security. Automated facial recognition and automated locker hardware integration are slated for future phases.

Data Structures Used & Justification

1. Encapsulated Record Structure (class CampusItem)

Each lost or found entity is modeled as an encapsulated C++ class grouping id, type (LOST/FOUND), name, category, colour, location, date, description, contact_name, student_id, claim_token, and status. Justification: Prevents disjointed parallel arrays and guarantees atomic object manipulation during sorting and database mapping.

2. Dynamic Contiguous Array (std::vector<CampusItem>)

The campus inventory is loaded into a std::vector<CampusItem>. Justification: The number of misplaced items varies dynamically. Unlike raw C-style arrays, vectors resize dynamically and provide contiguous memory cache locality, optimizing CPU instruction cache performance during iterative searches and sorting.

3. Priority Queue / Max-Heap (std::priority_queue)

Employed in dsa::findRankedMatches() with custom comparator MatchComparator. Justification: Pairing N lost items with M found items produces N × M pairs. Sorting all pairs using QuickSort or Merge Sort costs O(K log K) where K = N × M. A Max-Heap dynamically holds the highest similarity score at the root in O(1) and extracts top-ranked candidates in O(K log 5) time, radically conserving CPU and memory resources.

4. Sorting Suite (Merge, Insertion, and Bubble Sort)

  • Merge Sort (O(N log N) Stable): Chosen as the default production sorter. Divide-and-conquer guarantees O(N log N) performance even in worst-case scenarios, and stability ensures that chronological registration order is preserved for items with identical dates.
  • Insertion Sort (O(N) Best / O(N²) Worst): Ideal for incremental additions. When 1-2 new lost items arrive into an already sorted list, Insertion Sort shifts elements in O(N) time with zero extra space (O(1)).
  • Bubble Sort (O(N²) Worst): Incorporated for educational benchmarking in the DSA Lab. Enhanced with an early-exit swapped boolean flag to terminate immediately when input is already ordered (O(N)).

5. Searching Suite (Linear vs Binary Search)

  • Linear Search (O(N)): Necessary for unsorted, multi-attribute filtering across category, color, location, and keywords simultaneously.
  • Binary Search (O(log N)): Applied after Merge Sorting by item name. Halves search intervals on each iteration, achieving lookup in 10 operations for 1,024 records.

6. Hash Table Inverted Index (std::unordered_map)

Maps categories to lists of record IDs (e.g., "Electronics" → [1, 4, 9]) for instantaneous O(1) average subset lookups, and powers the bilingual English-to-Marathi translation engine.

#include <iostream>
#include <vector>
#include <string>
#include <iomanip>
#include <algorithm>
using namespace std;

// Encapsulated record representing a campus misplaced belonging
class CampusItem {
private:
    int id;
    string type;        // "LOST" or "FOUND"
    string name;        // e.g., "HP Pavilion Laptop 15s"
    string category;    // "Electronics", "ID & Cards", etc.
    string location;    // e.g., "Central Library 2nd Floor"
    string claim_token; // e.g., "DYPTC-LST-01"

public:
    CampusItem(int itemId, string itemType, string itemName, 
               string itemCat, string itemLoc, string token)
        : id(itemId), type(itemType), name(itemName), 
          category(itemCat), location(itemLoc), claim_token(token) {}

    int getId() const { return id; }
    string getType() const { return type; }
    string getName() const { return name; }
    string getCategory() const { return category; }
    string getLocation() const { return location; }
    string getClaimToken() const { return claim_token; }

    // Overload < operator for alphabetical sorting
    bool operator<(const CampusItem& other) const {
        return name < other.name;
    }
};

// Displays campus inventory in a clean institutional tabular format
void displayInventory(const vector<CampusItem>& items) {
    cout << left << setw(4) << "ID" << setw(7) << "Type" 
         << setw(24) << "Item Name" << setw(14) << "Category" 
         << setw(18) << "Location" << "Token\n";
    cout << string(68, '-') << "\n";
    for (const auto& item : items) {
        cout << left << setw(4) << item.getId()
             << setw(7) << item.getType()
             << setw(24) << item.getName()
             << setw(14) << item.getCategory()
             << setw(18) << item.getLocation()
             << item.getClaimToken() << "\n";
    }
}

// Linear Search: Sequential O(N) lookup across active catalogue
int linearSearchByName(const vector<CampusItem>& items, const string& target) {
    for (size_t i = 0; i < items.size(); ++i) {
        if (items[i].getName().find(target) != string::npos) {
            return static_cast<int>(i); // Found at index i
        }
    }
    return -1; // Item not found
}

// Binary Search: Divide-and-Conquer O(log N) lookup on pre-sorted inventory
int binarySearchByName(const vector<CampusItem>& items, const string& target) {
    int low = 0, high = static_cast<int>(items.size()) - 1;
    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (items[mid].getName() == target) return mid;
        if (items[mid].getName() < target) low = mid + 1;
        else high = mid - 1;
    }
    return -1; // Target element not found
}

// Bubble Sort: In-place sorting with O(N) early-exit optimization
void bubbleSortByName(vector<CampusItem>& items, bool ascending = true) {
    const size_t n = items.size();
    for (size_t i = 0; i < n; ++i) {
        bool swapped = false;
        for (size_t j = 0; j + 1 < n - i; ++j) {
            bool condition = ascending ? (items[j + 1] < items[j]) 
                                       : (items[j] < items[j + 1]);
            if (condition) {
                swap(items[j], items[j + 1]);
                swapped = true;
            }
        }
        if (!swapped) break; // Best Case O(N) if already ordered
    }
}

Conclusion, Future Scope & References

1. Conclusion

The Smart Campus Lost & Found System successfully bridges theoretical Data Structures & Algorithms with a production-grade campus utility. By implementing pure C++17 algorithms, the application proves that:

  • Merge Sort offers predictable, stable O(N log N) sorting for institutional inventories regardless of dataset disorder.
  • Binary Search delivers logarithmic O(log N) item retrieval when paired with pre-sorted structures.
  • Max-Heap Priority Queues provide an optimal approach to ranking candidate matches without executing costly full O(K log K) sorting over Cartesian pair products.
  • Dynamic Programming (Levenshtein) and Jaccard Set Overlap successfully compensate for human spelling inconsistencies and keyword order variations.
  • Zero-Knowledge Blind Custody (RBAC) ensures rigorous protection against fraudulent claims, while retaining complete administrative transparency for academic viva evaluation.

2. Future Scope

  1. OCR Student ID Scanning: Integrate lightweight Tesseract C++ OCR to auto-populate student roll numbers from photos of campus ID smart cards.
  2. IoT Gate Integration: Connect physical turnstile RFID readers at Gate 1 and Central Library to verify student presence during item retrieval handovers.
  3. Automated SMS / Push Dispatch: Integrate Twilio / SMTP gateway in C++ to instantly send SMS alerts to students when an automated match exceeds 85%.
  4. Cross-Campus Federated Deployment: Expand the database to synchronize across other D. Y. Patil group campuses (Akurdi, Pimpri, Navi Mumbai).
  5. Deep Neural Embedding: Augment token-based Jaccard similarity with ONNX C++ vector embeddings for image-based visual similarity matching.
